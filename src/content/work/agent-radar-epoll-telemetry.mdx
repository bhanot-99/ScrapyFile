## 1. The Engineering Dilemma: Autonomous Agents on Bare Metal

Modern AI coding agents (such as Claude Code, OpenHands, and Devin) are not passive LLM chat interfaces. They are autonomous Linux execution runtimes. During a single multi-step task, an agent spawns numerous transient bash subshells:
```bash
# Typical microsecond subshells spawned by autonomous agents
bash -c "cargo check --message-format=json 2>&1 | head -n 40"
bash -c "curl -s -X POST https://telemetry.internal/ping -d @state.json"
bash -c "git diff HEAD~1 > /tmp/.patch_cache"
```

To the Linux kernel, these processes often exist for transient bursts before exiting.

Traditional observability stacks run into challenges:
1. **Periodic polling (`/proc` scanners every 100ms):** Frequently miss short-lived subshells that fork, write to disk, open a network socket, and exit between poll intervals.
2. **`auditd` & root-level kernel tracepoints:** Flood system logs (`dmesg`), require `CAP_SYS_ADMIN` root privileges, and impose severe CPU throttling penalties on developer workstations.

We engineered **Agent-Radar** in Rust to explore an unprivileged approach: kernel event multiplexing using `epoll` and `inotify` with **kernel-level non-polling event sleep** during blocked wait states.

### Kernel Multiplexing in Rust with `nix::sys::epoll`
Below is the core loop demonstrating unprivileged multiplexing:

```rust
// File: src/watcher/epoll_loop.rs
use nix::sys::epoll::{epoll_create1, epoll_ctl, epoll_wait, EpollCreateFlags, EpollEvent, EpollOp};
use std::os::unix::io::RawFd;

pub fn listen_events(inotify_fd: RawFd) -> Result<(), Box<dyn std::error::Error>> {
    let epoll_fd = epoll_create1(EpollCreateFlags::EPOLL_CLOEXEC)?;
    let mut event = EpollEvent::new(nix::sys::epoll::EpollFlags::EPOLLIN, inotify_fd as u64);
    epoll_ctl(epoll_fd, EpollOp::EpollCtlAdd, inotify_fd, Some(&mut event))?;

    let mut events = [EpollEvent::empty(); 16];
    loop {
        // Blocks thread in kernel space until inotify reports an event (non-spinning sleep)
        let num_events = epoll_wait(epoll_fd, &mut events, -1)?;
        for ev in &events[..num_events] {
            handle_event(ev)?;
        }
    }
}
```
