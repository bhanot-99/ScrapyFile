## 1. Executive Summary: The Data Sovereignty Challenge in Local AI

As organisations deploy AI assistants onto workstations and edge environments, security teams face a fundamental dilemma:
> **How do you run local language models without risking intellectual property theft via unintended outbound socket connections, telemetry leaks, or model weight exfiltration?**

Standard containerisation (Docker, Podman) has operational trade-offs: containers require root daemons or elevated user namespace privileges, and a misconfigured port forward or environment variable can expose internal inference streams to external actors.

**NeuroOS** proposes a zero-trust, kernel-enforced runtime architecture designed specifically for on-device Small Language Models (SLMs). By combining **Linux Landlock LSM**, strict **seccomp-bpf filters**, and **BitNet b1.58 ternary quantization**, NeuroOS provides strict kernel-level egress isolation with zero GPU requirement.

## 4. The Sandboxing Architecture

<ArchitectureDiagram type="landlock-sandbox" />

### Kernel-Level Landlock Enforcement in C++20
Once model weights are loaded into read-only memory, the runtime voluntarily restricts its own system call privileges using Linux Landlock:

```cpp
// File: src/security/landlock_enforce.cpp
#include <linux/landlock.h>
#include <sys/prctl.h>
#include <sys/syscall.h>
#include <unistd.h>

bool enforce_zero_egress_sandbox() {
    // 1. Prevent privilege escalation via setuid
    if (prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0) != 0) {
        return false;
    }

    // 2. Define Landlock ruleset restricting network socket creation
    struct landlock_ruleset_attr ruleset_attr = {
        .handled_access_fs = LANDLOCK_ACCESS_FS_READ_FILE,
        .handled_access_net = LANDLOCK_ACCESS_NET_BIND_TCP | LANDLOCK_ACCESS_NET_CONNECT_TCP,
    };

    int ruleset_fd = syscall(__NR_landlock_create_ruleset, &ruleset_attr, sizeof(ruleset_attr), 0);
    if (ruleset_fd < 0) {
        return false; // Landlock not supported on kernel < 5.13
    }

    // 3. Apply the ruleset to the calling thread and its children
    return syscall(__NR_landlock_restrict_self, ruleset_fd, 0) == 0;
}
```

## 5. Security Verification & Implementation Notes

- **Network Isolation:** Validated by testing socket creation (`AF_INET`/`AF_INET6`) following Landlock restriction, returning `EACCES` (Permission denied).
- **Filesystem Isolation:** Non-whitelisted paths are completely masked from the process.
